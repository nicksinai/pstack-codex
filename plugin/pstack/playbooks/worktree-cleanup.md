# Worktree and simulator cleanup

Own the disk assessment and the safety gate. Reclaim merged or explicitly abandoned worktrees and stale simulator/cache state under the user's cleanup scope. Deletion has no code review to catch loss; these gates supply that review. Read [capabilities](../references/compatibility.md), [delegation](../references/delegation.md) before fan-out, and [history](../references/history.md) before touching chat records.

## Snapshot and audit

Record `df -h` for the filesystem containing the repository and each candidate; `/` alone may not hold all worktrees. Resolve the current repo and trunk from its configuration/forge, preserving the verified ref and timestamp. Use Git's registered paths, including hidden managed directories, rather than hand-typed guesses.

Run the bundled [auditor](../scripts/worktree-audit.sh) with a quoted repo path, for example `bash "<plugin-root>/scripts/worktree-audit.sh" "<repo>" --trunk "<verified-trunk-ref>" --github`. Requirements: Python 3.9+, Git supporting NUL-delimited `worktree list --porcelain -z`, and optionally recipient-authenticated `gh` for GitHub PR metadata. Locate the actual installed bundle; plugin-root is a placeholder, not a promised environment variable. Background slow audits through the host's supported process facility and collect their exit status/output.

The auditor reads registered worktrees, HEAD age, byte size, tracked changes, untracked and ignored names, branch upstream ahead/behind, ancestry, and optional PR/activity metadata. It writes JSON to stdout only. It does not fetch, delete, prune, create temporary files, scan histories, or modify Git refs/index; `GIT_OPTIONAL_LOCKS=0` disables optional index refresh. `--github` performs network metadata reads and may use the recipient's credential helper. Size is apparent file bytes, not guaranteed allocated/reclaimable bytes; HEAD age is commit age, not last use. Missing tools, partial reads, absent refs and unknown activity stay on hold.

If current remote evidence is required, obtain task authorization for a separately named `git fetch <remote> <refspec>`; it writes local refs/network state. Then rerun the audit and report freshness. Determine current trunk rather than assuming `origin/main`: explicit `--trunk` wins, otherwise only configured `origin/HEAD` is used. Missing default means unknown ancestry. Audit does not authorize a fetch or broaden a read-only request.

## Resolve actual usage

Buckets are advice, never permission. Get the pinned and active chat/worker set from the user or an exposed host tool. Cross-check every candidate, including sibling arena/reproduction trees owned by pinned or active parents. Sidebar names alone miss child worktrees. A recent timestamp never proves liveness; old timestamps never establish abandonment.

For `verify-recent-chat`, unknown activity, or any doubt, delegate disjoint scoped history reads when supported. Use the history contract to establish metadata workspace identity before content. Include intentionally identified child trails for this cleanup scope. Report chat/worker IDs, source locators, paths touched, and current pinned/active evidence; keep raw records private. For paths mentioned by scoped chats, verify canonical exact path boundaries, not substring or regex matches. If history or current host liveness is unavailable, name the gap and hold the candidate or obtain a user decision on that exact worktree.

The auditor can consume a private, task-local `--activity` JSON evidence file produced from that assessment. Creating this file is a separate temporary write, not part of read-only auditing. Format: `version: 1`, `repository: <canonical primary worktree>`, `observed_at: <timezone-bearing ISO timestamp>`, `worktrees: {<canonical path>: {active: <boolean>, pinned: <boolean>, last_activity: <timezone-bearing ISO timestamp>, sources: [<precise history and current-liveness locators>]}}`. Observation must be within one hour; malformed/unknown evidence fails closed. `last_activity` within four days produces `verify-recent-chat`; active/pinned produces in-use. This evidence is an agent/user assertion with citations, not independent proof. Recheck liveness immediately before cleanup. Keep private evidence outside the plugin and shared output.

## Decide and prune

For each proposed worktree show branch/HEAD, size, age, integration evidence, upstream freshness/ahead count, PR state, tracked diff and named untracked/ignored data, chat/worker owners, managed status, and reason to remove or hold. Closed PR alone is not proof of merge; a squash-merged PR counts only when its head matches this HEAD. Newer local commits, unpushed work, missing upstreams or unavailable PR state stay on hold. An explicitly abandoned branch needs a user decision even if an old PR is closed.

Tracked WIP requires showing the diff and obtaining a disposition before loss. Untracked `scratch:N` is a hypothesis, not a disposable-data guarantee: name the files and establish that each is throwaway. Ignored builds may hide valuable local databases, secrets, recordings or outputs: inspect metadata/disposition within scope. Preserve anything unresolved. A clean, integrated, pushed, not-in-use worktree can proceed under an already authorized cleanup request once lifecycle checks pass; otherwise obtain the decision required by the host and user. Preserve branch refs and unpushed commit reachability; explicitly chosen deletion of unique data must identify that loss.

Determine whether each checkout is app-managed before selecting the operation. Where the recipient exposes supported artifact/lifecycle tools, list the calling chat's attachments and use the exact identity returned by its lifecycle API. For managed checkouts, archive through that API so recoverable changes are snapshotted; preserve needed ignored files separately. Primary, pinned, shared, embedded-repository or initialized-submodule constraints may prohibit archiving. A worktree registered to another chat is not owned by this chat merely because Git lists it. Hold it until its authorized owner/lifecycle is established. Missing management tools do not authorize shell removal of a potentially managed checkout.

For confirmed ordinary unmanaged worktrees, first re-read HEAD, status, owners and the exact registered path to detect intervening work. Use quoted `git worktree remove -- "<path>"` without force for a clean candidate. If it refuses, inspect the actual cause and renew the disposition before escalating to `--force`. Delete residual ignored build directories only after validating the canonical exact candidate path, confirming registration removal and enumerating approved disposable contents; a blanket recursive deletion is not a fallback. `git worktree prune` is a separate registration mutation: inspect `--dry-run --verbose` output first, and act only within the authorized confirmed set. Keep the primary/current checkout and branch refs.

## Simulators and other reclaimers

On macOS with the appropriate Xcode tools, inspect simulator devices/runtimes and current test owners. Under explicit cleanup authority, target unused XCTestDevices clones (`xcrun simctl --set testing ...`), unavailable devices and specifically selected old runtime IDs; upstream's `delete all` is acceptable only after every member of that selected testing set is confirmed disposable and idle. Stop active tests before deleting their devices. Enumerate first and verify the supported `simctl` version's syntax.

Other candidates include Xcode DerivedData, iOS DeviceSupport, and pnpm/uv/brew/yarn caches. Use each tool's supported cleanup path and inspect usage/retention first. Cursor application backups/snapshots are not Codex caches; Codex conversation/session storage is user history, not disposable cache. Discover documented recipient-specific cache locations rather than inventing a Codex replacement for Cursor's path. Clear only authorized disposable caches the user has not asked to retain. On other platforms report unavailable simulator tooling and continue with applicable reclaimers.

Re-list worktrees and record `df -h` after cleanup. Reply with before/after and observed space reclaimed (other concurrent disk activity may affect it), exact worktrees/simulator/cache items removed or archived, preservation location where relevant, and a one-line reason for every hold, including the chat/worker or data that blocks it. An assessment-only request ends with this recommendation report and no cleanup.
