# Autopilot-stack

**You own the stack, never the landing. Build and verify the queue with full autonomy, then hand the operator one linear base-branch stack to review and land.** The sibling of **Autopilot-full**.

Read [delegation](../references/delegation.md), [PR delivery](../references/pr-delivery.md), [program state](../references/orchestration.md) and [continuation/recovery](../references/continuation.md) before starting. Bind actual host spawn/result/wait/stop controls and validated GPT roles; local workers replace cloud agents. Each writer gets an explicit isolated checkout, branch, base SHA and runtime resource reservation. These playbooks authorize scoped delegation when explicitly selected; installation alone supplies no task or merge authority. Independent GPT lanes lack upstream provider diversity.

Keep a recipient-private program store and invocation/checkpoint record using the shared contracts. Record the mode, queue, operator-owned items, explicit go/stop and delivery limits, owner and child IDs, exact current branches/heads/bases, findings, verdict receipts, countersigns, audit cadence, owned processes and next action. Program ledgers use exact-head identity. Shipping's narrow patch-ID retention can preserve specific lane evidence, but record the new head and recheck current CI/mergeability; it never turns a stale ledger row into a current-head pass. No PR merges merely because a helper labels it verified.


1. **Run the owner loop unchanged.** Resolve the forge once for the program through PR delivery, using supported built-in PR operations where the host requires them. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr ...` for PR create, edit, view, watch, and merge operations. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`). One isolated local owner per PR owns its change end to end: build, first push, a ready PR opened before self-proof, self-proof (gates, CI, receipts), skeptical Bugbot triage per [Bugbot triage](../references/bugbot-triage.md), a slop-strip ([deslop](../skills/pstack-deslop/SKILL.md)), [no-comments](../skills/pstack-no-comments/SKILL.md), and babysit to green per [Babysit](babysit.md). Owners parallelize when the work is self-contained. Within about 15 minutes, every owner starts a `decisions.tsv` trail per [show-me-your-work](../skills/pstack-show-me-your-work/SKILL.md), pushes its first branch snapshot, and opens the PR ready, never draft. After that, the owner pushes its branch again after every verifiable unit (hooks on, a WIP commit is fine). Keep the trail uncommitted and return it in the report. Owners also keep the `children.tsv` of [Autopilot-full](autopilot-full.md) step 2.
2. **Audit on a real loop.** The root runs an audit tick every hour. On the operator's go, bind the actual hourly active-session audit wait per [Autopilot-full](autopilot-full.md) step 6 and the continuation contract. Requested scheduling is separate from an in-session wait; app closure/sleep cannot be bridged by this playbook. Never leave cadence to memory or lossy completion notifications. At each tick, re-read this installed playbook at its reviewed package identity, reconcile current operator limits, and audit the operation against it. Do not assume the recipient's trunk contains the plugin or silently adopt unreviewed remote updates. Fix drift during that tick. Probe each owner with a generic liveness or status check. Count only side effects as progress: commits, pushes, PR or check deltas, and store reports. Treat a lane that passes its expected runtime without a side effect as stuck. Stand it down and dispatch a replacement at once. Do not wait for a polite return. Probe all subagents and end the tick per [Autopilot-full](autopilot-full.md) step 6.
3. **Hold the operator gates.** State-then-wait, so a request to state the plan is not a go. On the operator's stop, every owner takes an immediate zero-writes hold.
4. **Verify each round.** The owner reports its code-ready head SHA once the shipped code is final, and STACK-READY with the exact head SHA when its loop is green. The root verifies each round per [Autopilot-full](autopilot-full.md) step 4, with STACK-READY in place of merge-ready. Nothing enters the stack unverified.
5. **Append on a clean verdict, never ship.** No owner or root merges, arms auto-merge, or closes a PR in this mode. A clean verdict appends the PR to the one linear base-branch stack, in verified order or an order the operator specified.
6. **Single writer on topology, parallel writers on builds.** Owners push only their own branches and report the tip, current base, and intended parent. The root is the only topology writer. Acquire the topology critical section, have the child owner hold writes, and reconcile the latest remote tip before touching its branch. Serialize append/rebase/retarget/frontier updates; builds in other isolated branches may continue. Retain expected head/base and mutation receipts in program state and release the held owner only after topology and verification state reconcile. To append a PR, fetch the intended parent, rebase the child branch onto that exact parent tip, push with `--force-with-lease` only after an `ls-remote` check, and set the PR base to the parent branch. Create it with `origin pr create --status open --base <parent-branch>` or `gh pr create --base <parent-branch>` according to the resolved forge. Retarget an existing PR with `origin pr edit <pr> --base <parent-branch>` or `gh pr edit <pr> --base <parent-branch>`. Only the root PR targets trunk. Never submit or register the chain through `gt`.
7. **Absorb drift at the root, then re-verify what moved.** The root fetches current trunk and rebases the chain from bottom to top. When a rebase surfaces conflicts in an owner's files, that owner fixes its own slice and the root pushes the result. A rebase rewrites every SHA above it and voids verdicts at the old SHAs. Apply the patch-id rule in [Shipping](shipping.md) at each verdict SHA. Anything that is no longer valid goes back through this playbook's step 4 before delivery. Re-run mergeability and CI after every rewritten push even when the patch-id is unchanged. The countersign rule is unchanged from Autopilot-full. A genuinely new pin raises a stop for the root's fresh countersign. Absorbing drift of landed values is not a raise.
8. **Deliver the chain.** The deliverable is one linear chain of verified PRs, reviewable bottom-up in the resolved forge, every link carrying its verifier verdict in the PR body or a comment when the host authorizes that publication. If posting is unauthorized, prepare the exact verdict locally and report that publication gate; do not declare the full delivery complete. The operator reviews and lands it, with their own clicks or by personally arming merge-when-ready. A subsequent explicit request for agent shipping is a new delivery transition through Shipping, not implied by STACK-READY.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

**Reply:** links to the stack root and tip, a one-line verdict summary per link, and anything parked or excluded with the reason.

## Hold, interruption and recovery

On a stop/hold, relay zero-writes to every owner and child immediately through actual controls, inspect each returned state and owned processes, and record any unconfirmed stop. Keep branches, dirty work, trails and briefs; never delete a checkout as cancellation. A pause retains the selected mode and authority limits. Resume only after operator release and [artifact-first recovery](../references/continuation.md): inspect Git/forge state before replaying a push, retarget or merge, reconcile current heads with verdict receipts, recover the audit deadline, and confirm worker liveness rather than assume IDs survived. Replace dead/unknown workers with fresh consolidated briefs after containing surviving writers. Inspect an uncertain merge receipt before choosing the next item. Changed patches invalidate old findings/verdicts under Shipping's explicit rule; missing controls, CI, live verification, forge authorization or an enforced approval keep the affected item blocked, never clean by default. Continue independent authorized work and report exact gates.

Resolve the actual trunk branch/ref from repository configuration rather than assuming `main` or `origin/main`; substitute that verified ref in the full-mode drift checks. Read package references relative to this installed playbook, not the user's project tree. External verdict posts and customer/team messages obey host authorization. A countersign only covers the operator's delegated approval scope and can never bypass a forge-enforced approval.
