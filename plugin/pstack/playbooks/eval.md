# Eval

**You own the experiment design. Plan, blind, run, synthesize.** This is a user-requested workflow for evaluating a variant; it is not the port's qualification gate and adds no mandatory testing program. The user requests evaluation explicitly or reaches it through pstack's selected mode. Read [arena](../skills/pstack-arena/SKILL.md), [delegation](../references/delegation.md) and [models](../references/models.md) as coordinator before framing. This workflow requests independent local delegation within the stated evaluation scope.

## Non-negotiables for blinding

- No `eval`, `test`, `judge`, `experiment`, `rubric`, `score`, `compare`, `benchmark`, `candidate`, or `arena` in any directory, file or prompt the candidate sees.
- The candidate prompt looks like an organic user request. State the goal, not the meta.
- No chain-eliciting cues. Do not ask the candidate to list which skills, principles or files it applied. Ask for design notes generally and grade chain-following from code shape and actual records, not self-report.
- Sanitize directory and slug names. Use project-shaped names a user might pick.
- Do not tell candidates other candidates exist. Keep mapping, rubric, other outputs and coordinator records outside their visible workspace/context.
- The judge can know it is judging, but sees outputs by sanitized label only, never by model name.
- Comparing two variants: one judge scores both sets in a single pass on one scale, blind to which set each came from.

## Steps

1. **Frame.** State the variant under evaluation and what behavior counts as success. Write 3–6 concrete criteria for the judge only. Hold them back from candidates. Name exact source versions/base commits and task scope in a private coordinator record.
2. **Set up sanitized environments.** Allocate each writer an isolated local worktree/branch under a project-shaped name, plus separate runtime resources under delegation.md. Plant context an organic task would have: a project skeleton and the variant's applicable instructions. Keep only the required variant material visible, and inspect its filenames, contents, inherited context and ancestor instructions for blinding leaks. If repository/package paths or instructions reveal the experiment, stage an authorized isolated sanitized snapshot instead and record the transformation privately; preserve the intended variant semantics. Do not modify governing host instructions to hide evidence. A host that leaks evaluation context or cannot isolate candidates makes blinding conditional or BLOCKED, not established. Filesystem sharing is not an enforced access boundary unless the host supplies one.
3. **Author one organic prompt.** Write what a user would type, with no leakage of what is measured. Give each candidate the same task and the minimum ordinary context, its assigned project-shaped cwd and output scope. Use supported fresh-context spawn when available; a child inheriting this evaluation conversation is not blind. Missing context isolation blocks a claim of blinded execution. Keep evaluation, judging and transcript-accounting instructions in coordinator/judge context only.
4. **Spawn N parallel candidates** on validated native GPT selections using arena's Phase B isolation and bounded batching. Give every writer its own sanitized directory and inspect cwd/branch correctness. Native GPT-only attempts replace upstream different-provider models; identical-model seats remain independent attempts with reduced diversity. Keep identity/variant mappings private. Preserve each result, errors and dropouts, and wait for terminal completion before judging. With fewer than two outputs, disclose the lost comparison and obtain replacement evidence before a comparative promotion recommendation.
5. **Spawn one blinded judge** using arena's Phase C after all candidate writes stop. Prefer a different validated native GPT model family from the parent's when available; Claude/Grok provider diversity is absent. The judge sees the rubric and all outputs by sanitized label, never model identities or variant mappings. Remove identifying output metadata using a recorded private transformation that preserves the substantive artifact. Read all outputs yourself in parallel with judging. For two variants, use one pass and one scale. If a judgment cannot be blinded, report that limitation before treating it as evidence.
6. **Verify the chain from actual execution records, not self-report.** Read [scoped history](../references/history.md) to bind actual host history/trace capabilities. Its availability alone does not prove full worker records exist. Use an exposed reader providing complete worker turns/tool records, or an authorized local execution record selected by verified workspace and worker/session identity. A documented app-server endpoint is not an installed plugin tool. Inspect the actual schema and record format. Scope reads to this evaluation's workers in its active workspace and declared time window; never glob unrelated user projects or private chats. Retain exact record locators for file-open evidence. Distinguish requested reads from successful reads, summaries from full traces, and unavailable records from zero reads. Unknown schemas fail closed. Grade chain-following from actual opened files plus the artifact's code shape. If full records cannot be obtained, output quality may be assessed but chain-following remains unresolved; no self-report, summary, path timestamp or claimed skill name can establish it. Do not recommend promotion on a chain requirement without evidence.
7. **Read every output yourself** end to end. Check the judge's criterion-level verdict against the artifacts and actual records. Disagreement means a model may be biased or the rubric ambiguous: read both rationales, resolve evidence, and synthesize rather than averaging. Keep dropouts and missing evidence explicit. Retain sanitized outputs and private mappings separately for authorized reproducibility; do not bundle personal transcripts or account configuration in the plugin.

## Reply

Return variant under evaluation, rubric, per-candidate notes, judge's verdict, your synthesis and a recommendation on whether to promote the variant. Identify actual native model/effort choices in the final authorized report, lost provider diversity, blinding conditions, sanitized-label mapping where appropriate, exact source/trace locators, dropouts and unresolved chain evidence. This workflow returns a reasoned recommendation; it does not automatically edit a skill, install a variant or publish it. Durable changes follow the governing workflow and user authority.

For any fresh judge receiving blinded artifacts, follow [context isolation](../references/delegation.md): omit parent history using the actual supported operation and sanitize the self-contained brief/artifact labels. Without context isolation, the blind comparison is BLOCKED; do not describe it as independent blinded evidence.
