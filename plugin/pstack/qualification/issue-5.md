## History and authority argument

History selection has two gates before body search: understood metadata matches the canonical requested workspace/time, then understood source/parent/kind excludes current duplicates and noisy child/eval/test trails. Topic matching runs only over that selected corpus. Unknown formats fail closed, so an unsupported local schema cannot silently widen private-history access. The contract distinguishes modification-time ordering, turn-time scope, execution evidence and worker liveness. Full page coverage/truncation are explicit; summaries cannot substantiate actual tool execution. This is an inspectable instruction invariant under reader compliance, not a hard sandbox or a universal deterministic transcript parser.

The local fallback intentionally requires a verified installed producer schema and known local store/export before extraction; it bundles no guessed path, global recursive scanner or new service. If the friend has neither supported history reader nor verifiable scoped export, history mining is blocked and the exact missing prerequisite is reported. A sufficient supplied capsule or pushed branch can satisfy relevant pickup/context cases, but cannot falsely establish full execution coverage. This recipient dependency is **conditional**, not an unresolved claim of guaranteed API availability.

Rationale source access is read-only and user-scoped. MCP API names in original examples do not authorize writes, account-wide mining, messages, expensive analysis-service calls, incident resolution or ticket edits. Raw private evidence remains in scoped workers/private task context; public presentation requires sanitation and source permission. These host authority adaptations are explicit differences from tool availability assumptions, not lost investigative categories.
