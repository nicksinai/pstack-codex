The reference records their fidelity limits and requires rechecking recipient availability. No host tool here proves installed-recipient access.

The binding identifies operation classes and required schema/output properties: current-chat authored message/page reads; forge PR/run state reads; current worker status snapshots; captured media identity/time; and rendered Mermaid or an available diagram/chart/image artifact channel. Current status must be read rather than manufactured by resuming workers, starting jobs or task work. Summary-only history remains insufficient where authorship/boundary/pending-action coverage is missing. Authentication and current reader availability are recipient premises. A report timestamp does not prove liveness. Numerical sources, units and derivations must support displayed values.

Upstream `/visualize` is a conditional companion, not a bundled or guaranteed tool. Rendered Mermaid or a reply-only local fact-grounded graphic provides the same picture contract when the actual host supports it. An unrendered code fence, Markdown table or invented UI image cannot satisfy it. Screenshots/video are reused when available; a missing screenshot is labeled without launching an app. The general control-UI setup pattern is deliberately not invoked. Missing history boundary or usable required visualization leaves full catch-up completion blocked. Unknown individual state remains an explicit evidence limitation as upstream permits.

No package transcripts, account configuration, credentials, personal paths, fabricated artifacts or installation changes are introduced. The read-only scope applies even when separate task authority exists. Bro's restatement operation is skipped explicitly while retaining its plain language instruction.
