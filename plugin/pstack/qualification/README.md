# Source-backed qualification

Each `issue-N.md` owns a narrow workflow argument. Record the pinned source locator, adapted counterpart, capability evidence, preservation argument, substitutions/assumptions, and status for every owned requirement. Use `established` for inspected source/configuration properties, `conditional` for a claim depending on a named environmental premise, and `unresolved` when evidence is missing. Never promote an unresolved core obligation to established.

The baseline ownership inventory and adaptation diff live in the source repository's `provenance/`. `qualification/capabilities.md` indexes official host contracts; `references/compatibility.md` is the shared runtime instruction contract. Add focused capability references as necessary and link from the shared contract. Keep per-ticket ledgers separate to permit independent ownership.

Source inspection establishes instruction content and deterministic properties under stated premises. It does not prove that an agent always complies, an unavailable service works, or an unobserved installation/UI action succeeded. Port qualification does not require a new behavioral test suite. Upstream testing, reproduction, and real-artifact verification remain workflow requirements when those workflows are invoked.

The [final whole-package argument](issue-15.md) closes all included source targets and links every per-ticket argument. Early frontier observations remain historical; final integration closure notes distinguish them from the complete candidate. The [source inventory](source-inventory.json) contains every pinned locator, primary owner, disposition and target.
