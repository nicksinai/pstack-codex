## Resource and authority argument

The controls contract requires an operation binding and identity check before driving. The shared delegation ledger records exact checkout/build, ports/processes/debug endpoints, browser profiles/tabs or PTYs, data and artifact directories, run owner and cleanup. Concurrent Git worktrees cannot satisfy these runtime reservations by themselves. Borrowed apps have serialized access and residue cleanup without unauthorized termination; run-owned identities are checked before teardown. All evidence locations survive and are checked after teardown. These establish the instruction-level resource invariants, with actual enforcement and tool success conditional.

Generated app-specific skills may adopt their intended invocation policy; this does not change the two pstack entries' explicit-only metadata. Existing app skills/configuration are preserved, and current project instructions choose the authorized target. Maintenance's source wave authorizes delegates only within that invoked workflow, not automatic execution on plugin installation. Shipping callers use the same control adapters rather than weaker duplicate evidence rules. No install, app launch, external mutation, credential use, live maintenance or prototype execution occurred while implementing this source slice.
