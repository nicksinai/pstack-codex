# Session pickup

You own the resume point. Read the prior trail; do not redo completed work. Read [history](history.md) for source binding, workspace scope, fidelity and permission rules, and [delegation](delegation.md) before assigning a long-trail read to a child. This workflow explicitly requests such a scoped read-only delegate when needed to guard the context window.

1. **Locate the specific prior trail.** Use the identified chat/export, user-supplied prior-agent URL, or pushed branch. Inspect metadata overview and last messages first, then scan backward for decision points. Use only metadata-confirmed active-workspace history unless another workspace was explicitly requested. The port supplies no cloud-worker service; a URL is a source to read through an available authorized reader, not a remote worker to revive. Parse long trails in a read-only child and keep its reduced timeline in the main thread. If identity, scope or full items cannot be established, report the exact gap instead of sweeping unrelated chats.
2. **Reconstruct operational state.** Record branch and worktree locations, base/current SHA, what already landed from logs and base diffs, open todos, decisions, PR state, inherited evidence/verdicts, worker/resource ownership and outstanding processes. The prior trail is authoritative decision input. Preserve it rather than re-deriving the plan. Verify current branches/artifacts independently; a timestamp or stored child ID does not prove a live worker. Missing worktrees and changed patches are explicit recovery facts.
3. **Diff done against pending.** Compare what shipped with the plan and name the exact resume point. Do not rerun prior repros or redo completed work just to rebuild confidence. Check inherited evidence against current artifact identity; when changes or missing evidence invalidate a claim, repeat only the affected verification and explain why. Distinguish inherited decisions, observed current facts and uncertain self-reports.
4. **Route remaining work and choose the verdict.** Continue execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. Hand the remaining scoped work and timeline to the matching installed mode playbook; the pickup workflow ends at this handoff. If the needed routed playbook/capability is missing, name it as blocked rather than improvising a replacement. Existing user delivery limits and approval gates carry forward; pickup cannot authorize a merge, deployment, message or schedule.
5. **Verify inherited claims against the original goal on the real artifact.** A passing prior self-report is not proof. Retain applicable original reproduction, review and live-artifact gates in the routed workflow. Report actual verification and remaining limits; changed work cannot inherit a stale passing verdict.

Reply with where the prior agent stopped, what you inherited versus redid (ideally nothing redone), the resume point and outcome. Preserve a concise continuation brief containing the scoped trail IDs/locators, branch/worktree/SHA, decisions, done/pending work, evidence, capability gaps and next owner when handing off. Keep it in recipient-owned private task storage, never inside the distributed plugin.
