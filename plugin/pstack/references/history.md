# Scoped history access

Shared contract for recall, session pickup, recovery and history consumers. Read [compatibility](compatibility.md) and [delegation](delegation.md). History access is conditional on the recipient's actual tools or a locally verified read-only export. Installation supplies neither account history access nor a universal transcript schema.

## Scope before content

Record canonical active workspace/repository location, requested topic, explicit date range and timezone, current chat ID, and excluded child/eval/test identities where available. “Recent” defaults to the last seven days ending now; “all” remains all and requires pagination rather than silently shrinking the range. Default to the active workspace. A named prior chat/branch goes to [session pickup](session-pickup.md). A complete supplied state capsule can skip recall mining; current artifacts still need checking.

Resolve workspace symlinks and file-URI encoding using the host's documented metadata conventions. Match the canonical cwd exactly, including explicitly identified worktrees only when they belong to the requested scope. A shared remote, similarly named folder or topic match does not authorize another workspace's conversations. Ask before expanding the workspace boundary. State the scope to the user before searching. Current chat context is usable as supplied context but exclude its stored duplicate from mining; exclude child/subagent, eval and test records from the recall corpus. A specifically requested child trail may be inspected for pickup after its identity/scope is established.

## Reader binding and fidelity

Prefer an exposed host history reader. Inspect its actual input/output schema and whether it returns summaries, user/assistant messages, tool calls/results, or complete stored execution items. Bind list/read/page operations explicitly. Read thread metadata first, including cwd, ID, source/parent/kind, timestamps and pagination. Filter by cwd/time before fetching content; if listing cannot filter, inspect metadata only and select in-scope records before content reads. Unknown cwd/kind is not an inclusion match. Exclude current and identified child/eval/test records before any topic search. Follow every required page for claimed coverage and disclose inaccessible, omitted or truncated pages.

The official [App Server documentation](https://learn.chatgpt.com/docs/app-server) describes `thread/list` with canonical cwd metadata and `thread/read` with `includeTurns:true`; omitted/false yields summary. These are client APIs, not proof of agent-callable tools. Use them only through a supported recipient integration, with version-matching schemas generated by `codex app-server generate-json-schema` where that integration requires them. Do not start a new service, resume a thread or install a runtime merely to read history. A host summary reader remains summary-only even if it exposes an `includeOutputs` option; inspect truncation and cursor behavior. Execution claims require original relevant execution items, not a retrieval summary.

## Local read-only fallback

If a host reader lacks sufficient fidelity, use a user-supplied export or known recipient-local Codex history store only after the host documents or reveals that location. Do not guess a Cursor path or recursively grep a user's home/history tree. Candidate discovery may enumerate file names and modification times in the identified store without reading conversation bodies. Order candidates by actual filesystem modification time, never UUID spelling; metadata turn times determine inclusion in the requested window. A modification time is neither activity proof nor worker liveness.

For each candidate, read only its metadata header first. Establish a version-specific parse profile from the installed producer's schema/documentation and a minimal known metadata record. The profile must identify session ID, cwd, source/parent/kind, timestamps, user/assistant item types, tool call/result linkage and compaction/truncation markers. For JSONL a `session_meta` record with `payload.id` and `payload.cwd` is a known example, not a universal promise. Validate its types and identity before any body read. Child provenance may live in producer-specific source metadata; absence of an understood kind/parent discriminator leaves eligibility unresolved. Unknown variants, missing metadata or ambiguous source records fail closed: skip and report them, or request the exact scoped export/reader needed. Do not display rejected bodies to diagnose scope.

After metadata confirms scope and eligibility, search the topic only in those records and read matching regions plus necessary surrounding decisions. For one or two chats, read directly; otherwise assign disjoint metadata-filtered slices to bounded read-only delegates. Raw transcripts stay with those workers. Distinguish original message/response items from duplicated event summaries and avoid double counting. Inspect original tool calls and results when claiming tools used, files read, commands run, errors encountered or verification outcomes. Match call/result IDs and preserve source ID plus turn/item or JSONL line locator. Missing, compacted or truncated original items remain a gap; a summary cannot prove execution. No mandatory parser is bundled because available local formats and discriminators are version-dependent; an ad hoc reader must remain read-only, scoped and schema-verified before extraction.

## Findings and continuation

Each chat finding includes chat ID, metadata-confirmed workspace, relevant time range, topic, user goal, decisions, unfinished threads, struggles/corrections, artifacts (PRs/tickets/branches), precise locators and fidelity/coverage limits. Cite UUID plus turn/item or line when possible. The coordinator receives reduced findings rather than bulk transcripts. Keep records in the user's private task context; do not bundle, publish or persist raw private history in plugin/config files. Sanitize any externally shared output.

Cross-check surfaced branches, worktrees, commits/diffs, PRs, tickets and deployment claims against the actual relevant artifacts. Preserve prior decisions as authoritative input without needlessly repeating completed work. A prior self-report is not verification of the original goal, and changed patches invalidate inherited verdicts. Read-only recall ends with its brief. Pickup hands remaining work to the proper authorized workflow; history access itself does not authorize new edits, messages, merges or schedules.

If history is unavailable, name the exact missing reader/export and the evidence you do have. Use a supplied capsule or scoped branch/PR trail where sufficient. Do not claim complete recall or execution audit from incomplete sources. Core history-dependent steps stay blocked until the recipient supplies access or explicitly accepts a narrower scope.
