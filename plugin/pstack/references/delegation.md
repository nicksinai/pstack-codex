# Local delegation contract

Read [compatibility](compatibility.md) and [models](models.md) before dispatch. This is an instruction adapter over the host's supported operations, not an installed agent runtime. Local Codex workers replace all upstream cloud workers. They share the computer and available services. Independent GPT attempts lack upstream Claude/Grok provider diversity.

## Preflight and operation binding

Inspect the actual exposed schemas for spawning a child, receiving terminal results, waiting, messaging/steering, interruption/cancellation and optional closing. Record the operation names and supported arguments in the task's local dispatch ledger. Use only those operations. Confirm spawn authorization from the user's request or applicable skill/AGENTS instructions. These selected workflows explicitly request delegation within their scope.

Determine available concurrency, current live children, remaining nesting allowance, allowed model/effort overrides and whether background work is supported. Read host configuration or tool documentation where exposed; never invent a fixed limit or assume unlimited nesting. If a limit is not reported, reserve a conservative bounded batch of at most four workers and let the host enforce its ceiling. When a nesting ceiling prevents child spawning, have the owning ancestor dispatch those workers with the same briefs and relay results. If that route is unavailable, report the exact blocked step. Bound total outstanding workers and queue excess work; N remains total workers, not concurrency. Default host inheritance remains unless setup selects validated overrides permitted by the current schema.

A missing spawn or result-receipt capability blocks delegated workflows. A missing required cancellation capability blocks races using first-pass cancellation and unattended control; select another race rule only with user agreement. Missing close support means record terminal agents as retained and respect the host's slot accounting. Never substitute invented outputs or silently simulate a panel with one agent. Prefer native asynchronous children; if spawn itself blocks, disclose loss of parallelism and request a scope decision for workflows requiring parallel workers.

## Context isolation and withheld information

When a workflow withholds a private rubric, candidate identity, competing result, or prior reviewer view, bind a supported fresh-context/no-inherited-history spawn option before dispatch. Supply a self-contained sanitized brief and only the permitted file pointers; a new agent ID alone does not establish context isolation. Confirm the operation actually omits parent history, and keep forbidden metadata out of the shared files as well as the brief. Read-only scope does not provide this separation. If the host cannot isolate context, report the blind/private-rubric requirement BLOCKED; do not claim a blinded independent judgment or silently use inherited context. Ordinary independent reviews still need separate workers and their stated scopes.

## Brief and isolation

Create one ledger row per worker: stable role/ID, parent owner, goal, consolidated directives, read/write scope, exact base SHA, checkout and branch, model/effort, required instruction paths, evidence/output location, runtime resource ownership, state and result. Supply file pointers rather than bulk pasted context where recipients can read those files. If the package is inaccessible from the worker, supply the exact required instruction contents explicitly; a path to an unreadable package is not initialization.

For every code writer, allocate a distinct worktree and branch rooted at the declared commit. Use managed worktree operations where supported, otherwise authorized local Git operations with quoted paths. Include its absolute checkout location in the brief and require the child to check its cwd, branch, base commit and applicable repository instructions before edits. Creating a worktree does not relocate a child. Require all edits and shell cwd arguments to address its assigned checkout. Stop on mismatch. Separate output-only writers get unique explicit output directories; artifacts that affect the same build are code-writing scope. Read-only explorers may share a checkout but receive explicit no-edit scope; this is an instruction unless a read-only sandbox is actually enforced.

Give each writer its own ports, dev-server/process ownership, browser profile/session and artifact directory, or serialize use through a named owner. Include reservations and cleanup responsibilities in the ledger. A Git worktree alone does not isolate these resources. Record artifact dependencies and ancestor/child ownership. Nested coordinators receive an explicit concurrency allocation, and must route work up when they cannot create children.

For playbook delegates, inject [poteto-agent initialization](poteto-agent.md). Routed skills such as how, why, interrogate, reflect and swarm retain their specialized prompt instructions rather than being forcibly wrapped in full mode. Every brief states required context reads, verification, output format and authority limits. Measurements name exact SHAs, sample count, meaning of a sample and execution order.

## Lifecycle and results

Spawn fresh children by default, including fix rounds, retries, follow-ups and next queue items. Consolidate original brief, later directives, prior report and branch into the fresh brief. Resume/message/follow up only when work strictly requires costly-to-move live state: its checkout, uncommitted edits or running process. A role survives its agent; returning from one round does not justify reusing that agent. Stop/hold orders are control, not reuse. Avoid interrupt-chained continuation that loses directives.

Track child IDs through actual terminal completion; a summary or old timestamp is not liveness. Wait using exposed bounded operations, retain errors/dropouts, and inspect results. The coordinator owns the work: review evidence and diffs and write its own synthesis, except how's presentation step intentionally preserves the explainer's prose. Do not accept a worker's assertion as verification. Close completed children when supported and preserve necessary state first.

For cancellation, send stop/hold or interrupt using the current schema, confirm actual state, and account for nested workers and running processes. A stopped chat does not prove all processes ended. Cancel remaining race workers under the declared selection rule after sufficient evidence. Preserve their branches/outputs and record incomplete work. Never delete a worktree as a cancellation shortcut. On interruption, retain the ledger and inspect live processes and Git state before recovery; surviving child IDs are not assumed.
