# Local program orchestration

Read this on entry to [orchestrate](../playbooks/orchestrate.md), when autopilot needs program state, before running helpers, and on recovery. The playbook owns framing, briefs, pilot, rolling window, drain, continuous landing, verification and escalation. [Delegation](delegation.md) owns operation binding and fresh-worker lifecycle, [continuation](continuation.md) owns checkpoints/scheduling/recovery, and [PR delivery](pr-delivery.md) owns review, babysitting and shipping authority. This is not another spawning runtime.

## Recipient setup

Requires a local filesystem, Bun supporting `--no-install`, Git, and authenticated `gh` for the GitHub adapter. Existing Graphite is optional. Confirm versions and actual schemas before use. The CLI uses Unix-style local filesystem/PID locking; network filesystems, shared stores across machines and Windows are not qualified. One coordinator owns writes to a program store; nested tracks get separate stores and publish immutable report pointers to their parent. Runtime resources remain explicitly reserved under delegation.

Choose an absolute recipient-owned dependency cache outside the installed plugin and outside shared source. Set `PSTACK_TOOLS_CACHE` for helper invocations only. Choose a separate private program store and pass `--store` (or invocation-scoped `ORCH_STORE`). Do not edit global agent settings or assume `PLUGIN_ROOT` is exported. Resolve the installed package's actual root from the loaded skill path.

```sh
PSTACK_TOOLS_CACHE="<absolute-private-cache>" bun --no-install "<plugin-root>/scripts/orch/orch.ts" --setup-dependencies --help
PSTACK_TOOLS_CACHE="<absolute-private-cache>" bun --no-install "<plugin-root>/scripts/orch/orch.ts" --store "<absolute-private-program-store>" init
PSTACK_TOOLS_CACHE="<absolute-private-cache>" bun --no-install "<plugin-root>/scripts/orch/orch.ts" --store "<absolute-private-program-store>" frontier set --repo "<checkout>" --prs 12,13
```

Replace placeholders with actual paths and quote paths, including spaces. Explicit setup copies the packaged scripts into a content-addressed cache and runs `bun install --frozen-lockfile --ignore-scripts` there. This is a network/dependency mutation: use only when authorized by setup or the task; ordinary launcher calls fail with setup guidance when dependencies are missing. No plugin directory, user configuration or global dependency installation is changed. The copied manifest/lock pin resolution; existing upstream dev dependencies are retained but lifecycle scripts are disabled. `--setup-dependencies` is consumed before the requested CLI command executes. Both orchestration and PR watcher keep the synchronous `ensureDependenciesInstalled()` API, restart the same launcher in the cache with the original cwd/arguments and `--no-install`, and return its exit status. A changed packaged script or lock yields a different cache identity. No cache eviction occurs automatically.

Concurrent setup fails closed on `.setup-lock`. After an interrupted setup, inspect the owning process and incomplete cache before removing only its setup lock and retrying. Cache content is recipient-trusted executable code, not a security sandbox. Keep it private. Removal means stop owned processes, retain needed program records, then remove only the recipient-selected cache; removing a plugin does not erase program evidence.

## CLI and state contract

Run `--help` and `<command> --help` for exact syntax. Commands: `init`; `unit add/set/get/list/counts`; `ledger record/check/summary`; `inbox push/drain/count`; `gate park/list/resolve`; `frontier set/show`; `status`; `standing show/add`. `--json` returns complete rows. Missing/malformed arguments return 1, absent records return 2, success 0. The state helper never creates/resumes/waits/cancels an agent. Only dependency bootstrap reexecutes its own launcher. Frontier discovery runs read-only `gh`, or optional `gt`/`git` queries; no merge, rebase, push, retarget or PR close occurs in the helper.

Store files preserve upstream TSV/JSON contracts: `preferences.md`, `overview.md`, `units.tsv`, `ledger.tsv`, `frontier.json`, `inbox/`, `gates.md`, `status.md`. The decision trail is owned by [show-me-your-work](../skills/pstack-show-me-your-work/SKILL.md). Every file has one declared writer; rows and unique inbox pointer files are updated through the helper at serialized drain points. `status` derives counts from actual tables; counts include historical ledger identities, so a total verdict count alone is not a current-head pass count. Before declaring done, match each current unit/PR head to `ledger check` and inspect its evidence, not just the derived summary.

Writes acquire `.orch.lock` exclusively with `wx`, retain it for that CLI operation, and release only when its PID still matches. Row/table replacements use unique temporary siblings and atomic rename. This establishes atomic individual file replacement on a local filesystem, not multi-file transactions or crash-proof durable storage. PID reuse can conservatively block stale takeover; unknown/live holders block unless explicit `--force` is used. Stale takeover is serialized through an exclusive recovery directory and rechecks the holder before unlinking. Never force takeover while another writer is active. A crash during takeover can leave a recovery guard requiring explicit owner reconciliation.

Inbox push stores one atomic unique pointer. Drain locks the store, snapshots current pointers, renames that inbox to `.inbox-drain-<pid>-<uuid>` and creates a fresh inbox. Arrivals use the next batch after the lock releases. The archive remains for crash recovery; record classification and resulting rows durably before marking a batch reconciled. The coordinator tracks reconciled archive identities in its checkpoint. Reconcile each pointer by unit/current head/receipt before replay so interruption does not double land or spawn work. Archive removal is an explicit owner action after durable reconciliation. No automatic archive cleanup or exactly-once process execution is claimed.

## Verdict identity and frontier

Ledger keys remain PR number plus exact head SHA. One program store covers one repository; otherwise identical PR numbers would collide. A fresh head has no matching record and `ledger check` returns NOT-VERIFIED. Record exactly `live-ui-verified`, `unit-test-verified`, `type-check-only`, `verifier-blocked`, or `verifier-failed`; labels do not run verification. A verifier record overrides a worker self-report; a later self-report without verifier identity cannot overwrite an existing verifier row. Named agents are instruction-governed identities, not cryptographically authenticated principals. Evidence pointers must actually resolve, and the coordinator validates author/independence. Blocked is never pass, failed requires a fix unit, behavioral work needs more than type-check-only. Changed patches invalidate prior verdicts; do not relabel a new SHA to reuse an old result. Program orchestration uses strict current-head identity even where a separate shipping workflow permits a narrowly evidenced patch-ID exception.

For GitHub, `frontier set --repo ... --prs <bottom-to-top-order>` validates every supplied PR from live `gh pr view` data, forbids duplicates/fork PRs/closed-unmerged PRs and checks the base link above each preceding open PR. It records live remote head SHAs, PR states, generation and lowest unmerged PR. The supplied order is an explicit complete-stack assertion, not automatic discovery; one stacker reconciles retargets/merged bases and confirms no omitted member before writing. No API snapshot can prevent later remote mutation: refresh immediately before an authorized merge and apply PR delivery gates. Omitting `--prs` selects upstream Graphite discovery in the stacker's configured clone, not a guessed GitHub stack. Other forges are unsupported by this helper; report that precise gap instead of interpreting GitLab state as GitHub.

Independent GPT review replaces cross-provider review; local workers replace cloud workers. Availability of nested control, model diversity, scheduling, authentication and live app verification stays conditional. Do not claim background progress through app closure/sleep or that a restored ledger makes an old child alive. Missing capability blocks the affected step, with exact artifacts/state retained for recovery.
