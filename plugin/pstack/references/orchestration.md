# Native program orchestration

Read this on entry to [orchestrate](../playbooks/orchestrate.md), when autopilot needs program state, and on recovery. The playbook owns topology and supervision; [delegation](delegation.md) owns worker controls, [models](models.md) owns validated GPT roles, [continuation](continuation.md) owns checkpoints and scheduling, and [PR delivery](pr-delivery.md) owns delivery authority and its separate PR watcher. Upstream 0.15.36 removes the custom orchestration CLI. Do not recreate that runtime, invoke the deleted helper, run coordinator polling scripts, or relay worker messages/status between agents.

## Bind actual capabilities

Inspect the current tool schemas before dispatch. Record supported spawn, result/wait, cancellation, optional stateful fork, project tracker/store, and PR/CI subscriptions. A name in these instructions is not an API. Use native child completion events and result waits. Do not use chat creation to emulate internal workers unless the user requested a new chat. A worker follow-up is for the same work, not a status query that wakes an idle agent. Read-only snapshots and direct artifact/forge inspection can establish current state without restarting workers.

Upstream's Project tracker (`notes.md`) and Project store have no universally exposed Codex equivalent. If an actual project-state tool exists, bind its read/write operations and record its identity. Otherwise explicitly substitute a private task directory under continuation: one coordinator-owned `notes.md` for the goal, unit checklist, PR dependencies and decisions, with separate worker-owned evidence/trails and immutable report pointers. This is an instruction-governed file store, not a native project service, transactional database or shared runtime. Keep its actual path in task context, outside the installed package and shared source. Only its declared owner writes each file. Persist complete replacement checkpoints before yielding and retain the previous valid record until replacement completes.

PR/CI event subscriptions are conditional. Record actual subscription identities, events/cursors and unsubscribe operation if exposed. If absent, disclose that event-driven PR monitoring is unavailable. Owners may complete their explicitly assigned Babysit/Shipping waits through PR delivery; the coordinator waits for their native completion/results and makes direct forge checks at decisions and before reporting. Do not substitute a coordinator shell polling loop or claim a durable event subscription. If the program requires a PR event wake and has neither a supported subscription nor an authorized owner wait, retain the checkpoint and report that precise missing capability.

## Ownership and recovery

Record each unit's scope, exact base/head, PR, sole branch writer, actual child ID, assigned role, state, evidence predicate, runtime/resource reservations, retries by cause, and decision trail. A coordinator never writes application code. Only the PR owner pushes, rebases or retargets; a parent decides destructive topology changes. Workers run in isolated local worktrees, not upstream cloud VMs, and share machine resources. Keep at most three levels and approximately ten concurrent workers per coordinator only where host capacity and resource reservations permit. Queue excess work without dropping required coverage.

Use a fresh worker for each independent task. Its brief contains the complete relevant upstream reports, goal, permitted/prohibited paths/actions, wrapper and instruction paths, and evidence required. A fork is useful only when the actual tool preserves required built state. Conversation history inheritance alone does not clone a checkout or process. Before replacing a stalled owner, preserve artifacts and reconcile/contain the original writer; never let a late result or surviving process overwrite the replacement's branch. Account for every child as done, replaced or absorbed, and retain the scope/evidence behind that classification.

For every PR record author and independent verifier identities, exact verdict head/base and evidence paths. Inspect the actual diff/artifact, not only a summary. Orchestrate requires an independent pass at the current head: a new push needs a fresh verdict. Autopilot and Shipping use their own explicitly stated patch-id and verification-effort exceptions; do not silently import those exceptions into Orchestrate. Blocked or unavailable live verification is never PASS. Green CI is an input, not independent behavioral evidence. Distinct GPT models can increase variation, but no GPT-only review is cross-provider diversity.

On recovery inspect actual worker controls, files, Git and forge state before replaying any mutation. Old child IDs, timestamps, notes and completed command requests do not prove liveness or successful merge. Native event waits and private files do not promise execution through app closure, sleep or offline services. Missing required controls block only the affected operation, with state/evidence retained for recovery.
