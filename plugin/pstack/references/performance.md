# Performance and forensic setup

Read this when a selected PStack route measures performance or diagnoses a runtime artifact. Select the installed `pstack-poteto-mode` entry for the request and name the route: Perf issue for a one-off measured fix, Hillclimb for sustained metric improvement, Runtime forensics for live diagnosis, or Trace forensics for an existing capture. For a number produced elsewhere, select `pstack-benchmark-checklist` or `pstack-principle-explain-the-number` directly. Confirm the recipient's picker identity under [compatibility](compatibility.md); internal reads use bundled paths and require no invented skill-invocation tool. Entry grants only the current request's authority.

## Bind the target and tools

Before a run, record the target process or supplied artifact, exact source revision, workload/data/state/concurrency, build/runtime configuration, environment and units. Keep baseline and after captures with their run commands and samples in a task-owned artifact directory outside the plugin. Give parallel workers separate checkout, process/port, browser session and output ownership under [delegation](delegation.md). Compare the same workload and configuration; record deliberate differences. Use the [benchmark checklist](../skills/pstack-benchmark-checklist/SKILL.md) before trusting each number.

Inspect available host tools, repository scripts, installed profilers/parsers and target permissions. Packaging these instructions installs none of them. Prefer the project's existing harness; bind the matching control adapter for browser/Electron/web or CLI/TUI work. The required adapters live at [references/control-ui.md](control-ui.md) and [references/control-cli.md](control-cli.md) relative to the package root. Read the relevant file before using it. If it is absent, or the exposed operations cannot reach the target, report the exact blocked capture/probe/verification step. A native or other runtime needs its actual supported attach/capture interface; do not assume CDP applies to every process. Executing an unrelated surface is not verification.

Resolve tools against the recipient's platform. `uptime` supplies load where supported; Linux `nproc` and macOS `sysctl -n hw.logicalcpu` supply logical core counts. CPU counters, I/O wait and syscall evidence require platform-appropriate available tools. The upstream examples (`top`, `pidstat`, `node --cpu-prof`, `py-spy`, `perf`, `strace -c`) are choices to inspect, not promised dependencies. Record the actual tool, version, command and output. When a required observation cannot be obtained, the gap remains conditional or blocked, and the relevant benchmark verdict stays inconclusive. Do not install profilers, add dependencies or change target permissions merely because a tool name appears here; use the task's existing authority and governing host instructions.

## Measurements and experiments

Read [Explain the Number](../skills/pstack-principle-explain-the-number/SKILL.md). Keep competing explanations for the number visible: actual limiter, failed work, cache/skipped work, untuned configuration, noise, and a micro result too small to change the end-to-end path. Rule them out with run evidence. Profile in a diagnostic run distinct from reported timings. Report units, sample count, median and range; retain the raw samples and execution order. The checklist's explicit single-run ballpark exception applies only to a requested ballpark, never a choice between options or a hillclimb win.

For [Perf issue](../playbooks/perf-issue.md), use baseline trace → architecture hypotheses → delegated scoped change → parent diff review → after trace → parsed comparison → cited PR. Apply the seven performance mantras in their stated order and stop once an earlier one meets the one-off target. Resolve the `perf-issue` role through [models](models.md), with local GPT execution in place of the original provider default.

For [Hillclimb](../playbooks/hillclimb.md), freeze the harness only after contrasting realistic workloads prove its sensitivity and the checklist passes. Preserve its error/work counts and green baseline regression gate. Define the metric, direction and stop predicate with both target and minimum attempts. Read the experiment's `decision.tsv` before every attempt; retain the playbook's exact columns. The [show-me-your-work](../skills/pstack-show-me-your-work/SKILL.md) run trail records the experiment setup, pivots, checkpoints and handback with pointers to that table and evidence, and owns its own transcript/reviewer audit. The experiment table is the specialized measurement ledger, not a replacement for that audit. Keep it gitignored as the playbook requires; do not commit private artifacts by default.

Resolve `hillclimb` through [models](models.md). Each isolated candidate gets a scoped hypothesis, frozen harness, regression gate and unique artifacts. Parallel independent candidates use separate worktrees; compare each against its declared base. Serialize acceptance into the canonical branch, then remeasure combined state before retaining a further change; separate successful branches do not prove their combination. One accepted commit per fix, with explicit file staging. Reject/revert a candidate in full when evidence fails, preserving unrelated work. Every attempt is checked and logged before the next; keep both accepted and rejected evidence. Borrow only the [unattended wake mechanism](continuation.md), retaining Hillclimb's stop predicate and pause/authority boundaries. Missing required worker capabilities block the delegated attempt rather than authorize silent coordinator implementation.

Use [PR delivery](pr-delivery.md) and [Opening a PR](../playbooks/opening-a-pr.md) at the measured code-change routes' delivery step. Keep one primary number in the PR, with detailed samples/limiter evidence linked. PR preparation does not authorize babysitting, merge or deployment.

## Forensic evidence and scope

[Runtime forensics](../playbooks/runtime-forensics.md) needs a reachable live process and the matching capture interface: CPU profile for a spin, heap snapshot for a leak, CDP trace for a visual glitch on a CDP-capable target. Reduce the artifact, then prove the surviving mechanism through live instrumentation (CDP evaluation or a live hotfix without reload where supported). Record the candidate explanations, probe, expected discriminating observation and actual result. A guess from source or a trace alone does not close the live mechanism gate. When this attach/probe capability is unavailable, report the exact missing operation and retain a hypothesis rather than invent a confirmed cause. Follow the control adapter's operational limits; an injection into a shared/production process requires the task's applicable authority. Record and clean up transient instrumentation. The diagnosis-only route permits scoped diagnostic probes within authority, not an unrequested persistent fix.

[Trace forensics](../playbooks/trace-forensics.md) consumes a fixed supplied capture; preserve the original. Identify format, parse/decompress with an available compatible tool, and reach a queryable representation before interpreting it. CPU/trace samples and frames, heap nodes/edges and retainer chains, or spindump threads/wait reasons must retain their original identities/units and a route back to the input. SQLite is the prescribed query shape where applicable; record parser/schema/query and artifact locators so reductions remain checkable. An unsupported/malformed capture, missing decompressor/parser or failed transformation blocks that step. Use an isolated read-only delegate for large artifact parsing under [delegation](delegation.md); keep only the reduced finding and evidence pointers in the parent.

Map findings via the artifact's symbols to file, symbol and line. If mappings are absent, resolve them or disclose that the artifact cannot supply them; the unmapped frame is not a diagnosis. A paired before/after capture can confirm the trace finding; without it, mark the strongest supported hypothesis explicitly. Do not recapture merely to substitute different data for the supplied artifact. Both forensic routes return a cited diagnosis and `throughput checkpoint: n/a, read-only forensics`, with no fix unless asked. When a fix is requested, hand off to [Bug fix](../playbooks/bug-fix.md) or [Perf issue](../playbooks/perf-issue.md) with the evidence; the new route retains its own gates.

## Qualification limits

The [issue #9 argument](../qualification/issue-9.md) establishes source preservation and instruction/reference properties. Actual process access, tool availability, profiling perturbation, symbol fidelity and agent compliance remain runtime conditions. Source inspection, successful compilation, a worker report, or a plausible timing cannot substitute for the route's required observations.
