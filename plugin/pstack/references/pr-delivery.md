# PR delivery contract

Use this contract for code-change delivery, learning PRs, comment cleanup, babysitting and requested shipping. Read [compatibility](compatibility.md) and [delegation](delegation.md). This is the authoritative cross-workflow delivery adapter. It does not activate these workflows by installation.

## Request and pause boundaries

A code-change workflow normally ends with [Opening a PR](../playbooks/opening-a-pr.md), ready for review. Honor a user's local-only, draft-only or other explicit delivery limit and stronger host instructions. PR creation does not ask for babysitting. [Babysit](../playbooks/babysit.md) starts only on a user request, or an explicitly authorized autopilot owner brief that assigns that loop. A merge, land, ship or merge-when-ready request routes to [Shipping](../playbooks/shipping.md); babysit alone stops at merge-ready.

Preserve upstream pause boundaries: deployment, data deletion, shared-branch force pushes and customer messages need the user's existing explicit authorization under the governing host. If it is absent, complete the authorized reviewable preparation, explain the concrete pending action, and pause that action. A request to ship a PR does not automatically authorize a production deployment or a shared-branch force push. `--force-with-lease` reduces a race; it does not confer authority. Ordinary fixes and reviewable preparation continue within scope. Explicit user limits remain binding.

External replies, verdict posts and team messages require authorization under the current host, even where upstream assumes it. A request to address review threads may authorize scoped replies under host rules; inspect those rules rather than infer blanket messaging authority from plugin activation. If posting is blocked, preserve the proposed reply/verdict and evidence locally, state what remains unsent and continue independent authorized work. Do not report the posting step complete. An approval gate imposed by the forge remains a wait.

## Tool and forge binding

Inspect the exposed built-in PR tool's schema. Use it for supported creation, editing, retargeting and ready operations; attachment alone is not those operations. Follow any host instruction to attach created PR URLs. For other operations, resolve one forge as Opening a PR prescribes. Record the selection and retain it across create/view/watch/merge. Origin is conditional on the executable resolving this repository; GitHub uses authenticated `gh`. Verify required commands, access and actual current PR state before claiming success. A missing forge operation is a blocker, not evidence of a successful action. Never put untrusted review text into executable shell text. Use structured arguments or data files, including body-file for multiline content.

## Cleanup and writing

Before commit run [deslop](../skills/pstack-deslop/SKILL.md). Before review run [no-comments](../skills/pstack-no-comments/SKILL.md), which injects the [Comment Sicko](comment-sicko.md) wrapper into a fresh child. Use [technical-writing](../skills/pstack-technical-writing/SKILL.md) then [unslop](../skills/pstack-unslop/SKILL.md) for titles, descriptions and commit bodies. Preserve the exact caller's base/diff and scope; default to the repository's main branch only when no base is given. The comment worker edits comments and flags code symbols, never application code. Its parent inspects and integrates the patch and owns application fixes. Missing spawn/result capability blocks no-comments; do not manufacture a fresh review.

The deslop instructions are adapted from `cursor-team-kit` 1.2.0 at the same pinned Cursor repository commit as pstack. Its [MIT notice](../licenses/cursor-team-kit-LICENSE) accompanies the adaptation. No runtime dependency on that plugin remains for deslop. No-comments and Comment Sicko originate in pstack itself.

## GitHub watcher and dependencies

Resolve the package directory from the actual loaded skill/reference location. Do not assume the working repository is the plugin directory, an environment variable such as PLUGIN_ROOT is supplied, or a personal installation path exists. The entrypoint is [watch-pr](../scripts/watch-pr/watch-pr). Execute `bun <absolute-package-path>/scripts/watch-pr/watch-pr` with each argument separately quoted and cwd set to the intended repository, or invoke the executable when Bun is on PATH. Spaces in the package path must remain one argument. Explicit `--owner`, `--repo` and `--pr` avoid ambiguous repository inference. The helper is read-only toward GitHub: it queries through `gh`, classifies state and emits verdicts. It neither merges nor arms auto-merge.

Preflight requires Bun, authenticated `gh` with read access to that repository, and the complete shared helper set `scripts/bootstrap.ts`, `scripts/package.json`, `scripts/bun.lock`. The shared bootstrap must establish the locked dependencies before importing cli.ts. Its dependency install is a real network/filesystem action: inspect its behavior and honor the host's dependency-install authority. Never edit recipient-global skills/configuration to make it run. If the installed package is read-only, use the shared bootstrap's supported recipient-owned writable cache/mirror and preserve the pinned manifest/lock; do not invent a cache environment variable. An absent helper set or unsupported writable-cache path blocks execution with the exact prerequisite named. Orchestration owns the shared bootstrap; final package qualification must close that dependency before claiming watcher readiness.

Default output is JSON/NDJSON; `--pretty` is the human four-column rendering. `--status-only` performs one status query, not a readiness assertion, and exits zero even when the reported verdict has blockers. Read the verdict, reason, observed head/base/check/review state and query failures, not exit code alone. Single and connected-stack modes can reach READY; frozen queued mode uses WAITING/merge-queue, ADVANCE and COMPLETE as Babysit specifies. Preserve the captured bottom-to-top list across rearms except the sanctioned already-merged-owner follow-up. A timeout/query-budget error is not CI failure or merge-ready evidence. Use `--timeout` to bound a process when the host requires it; restarting a bounded watcher is one rearm, never a second parallel poller.

## Active-session continuation

Cursor's `/loop` is replaced with the host's actual background-process and bounded wait/result operations. Start one watcher, retain its process/session ID, consume each emitted event, act under the selected playbook, then rearm after a push or handled verdict. Bound waits so user questions receive a reply and progress updates continue, while the same watcher owns polling. Do not run a second sleep loop. For queued Babysit, stop the process after the blocker-free WAITING/merge-queue event rather than waiting for a merge. For Shipping, retain the frontier watch until the active forge confirms merged or the playbook's hard failure. Distinguish cancelling the tool wait from terminating the watcher process and confirm termination when stopping.

This is active-session work while the app/computer and required services remain available. It is not durable scheduling and does not survive app closure or sleep by contract. A recurring automation requires a separate user request and supported host scheduler. If background execution, bounded result consumption or cancellation is missing, report the exact incompatible loop operation; a one-pass check remains available, but does not establish drive/background compatibility. Preserve mode, forge, frozen queue, frontier, head/base SHAs, process owner, triage/retry decisions and verdict artifacts in the task's recovery record. On interruption inspect actual Git/forge/process state before restarting; old process IDs and timestamps do not prove liveness.

## Independent shipping evidence

Each PR gets one fresh independent GPT verifier that did not write its code. Allocate explicit parent/head worktrees, runtime resources and artifact locations. Use the project's existing verification harness and the matching supported real UI/terminal control instructions; discover the host's actual schemas before use. Preserve parent-versus-head observation, fresh snapshot/action/check for UI, or real terminal input/output for CLI, deterministic waits, screenshots/transcripts/build artifacts and cleanup. A source review, CI pass or approving bot does not replace this lane. If the matching control instructions/tool or real surface is unavailable, leave the lane unresolved and do not mark PASS. The UI/terminal companion slice supplies the full control instructions; final qualification must establish their closure.

Record verifier identity, PR, exact verdict head/base SHAs, stable base-to-head patch-id, exercised surface, command/action sequence, actual evidence paths and PASS/PASS+NOTES/FAIL. The parent inspects evidence before accepting it. Preserve Shipping's patch-change revalidation, special build-noise argument and one-at-a-time merge protocol exactly. Changes without retained build outputs require rerunning the lane; changed production patches require re-verification. The port's proof-oriented qualification does not waive these user-workflow checks.
